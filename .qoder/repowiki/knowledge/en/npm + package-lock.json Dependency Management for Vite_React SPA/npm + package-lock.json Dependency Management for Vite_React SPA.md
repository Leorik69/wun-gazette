## Approach

This is a small Vite + React + TypeScript frontend project that uses **npm** as its package manager. Dependencies are declared in `package.json` and pinned via the generated `package-lock.json`. There is no vendoring, no private registry configuration, and no `.npmrc` file — all packages resolve against the public npm registry (`registry.npmjs.org`, confirmed by the `resolved` URLs inside `package-lock.json`).

## Key Files

- `package.json` — declares runtime dependencies (`react`, `react-dom`, `three`, `lucide-react`, `@types/three`) and dev dependencies (`vite`, `@vitejs/plugin-react`, `typescript`, `@types/react`, `@types/react-dom`). The package is marked `"private": true`, which prevents accidental publication to npm.
- `package-lock.json` — deterministic lockfile produced by npm; it pins every transitive dependency (including nested `@babel/*`, `@esbuild/*`, etc.) to exact versions under `https://registry.npmjs.org/...` tarballs.
- `.gitignore` — excludes `node_modules` and `dist`, so the dependency tree is never committed; only `package.json` and `package-lock.json` are version-controlled.
- `vercel.json` — deployment config on Vercel; no custom registry or install hooks are present, so Vercel installs via standard `npm ci` / `npm install` behavior.

## Versioning Conventions

All versions in `package.json` use the caret (`^`) range operator (e.g. `"react": "^19.2.0"`, `"vite": "^7.1.12"`, `"typescript": "^5.9.3"`). This allows minor/patch upgrades within the major version while still being constrained. The lockfile then resolves these ranges to exact semver versions at install time.

## Build-Time Enforcement

The `build` script runs `tsc --noEmit && vite build`, meaning TypeScript type-checking is enforced before bundling. Type-related dependencies (`@types/react`, `@types/react-dom`, `@types/three`) are therefore not optional — a mismatch between runtime types and their `@types/*` counterparts will fail the build.

## Vendoring / Private Registries

No vendored dependencies exist. No `.npmrc`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, or `bun.lock` files are present. No `GOPRIVATE`, `NPM_CONFIG_REGISTRY`, or similar environment variables are configured in the repo. All third-party code comes from the public npm registry.

## Constraints Observed

- `node_modules` is gitignored, so dependency trees must be reproducible from `package.json` + `package-lock.json` alone.
- The package is private (`"private": true`), preventing accidental publishing.
- Runtime and type dependencies are kept in sync: `react`/`react-dom` are paired with matching `@types/react`/`@types/react-dom` versions, and `three` is paired with `@types/three`.
- No postinstall scripts, preinstall hooks, or custom registry overrides exist in `package.json`.
